# VK ID: подключение входа

Публичный вход реализован без запроса email и телефона. Приложение получает у
VK ID только постоянный идентификатор пользователя и имя, создаёт локальную
сессию LPVOLLEY и сразу забывает access token VK.

## Настройка приложения VK ID

1. Создать веб-приложение в кабинете подключения VK ID.
2. Указать доверенный домен `lpvolley.ru`.
3. Добавить точный redirect URL:
   `https://lpvolley.ru/api/auth/vk/callback`.
4. Скопировать числовой ID приложения, не публикуя ключи доступа.
5. На сервере задать:

   ```env
   VK_ID_ENABLED=true
   VK_ID_APP_ID=<числовой ID приложения>
   VK_ID_REDIRECT_URI=https://lpvolley.ru/api/auth/vk/callback
   ```

6. Применить `migrations/076_vk_id_auth.sql`, собрать приложение и перезапустить
   web-service.

Если любой обязательный параметр отсутствует, VK ID остаётся выключенным и
кнопка не отображается.

## Защита

- OAuth 2.1 Authorization Code с PKCE S256;
- случайный `state`, привязанный к HttpOnly/SameSite=Lax cookie браузера;
- intent действует 10 минут и потребляется один раз;
- callback проверяет `state` и совпадение VK user ID в token/user-info;
- redirect после входа допускается только на внутренний путь LPVOLLEY;
- access/refresh token VK и email/телефон не сохраняются;
- существующие email-аккаунты не объединяются автоматически: это защищает от
  захвата аккаунта по совпавшему адресу или имени.

## Привязка к существующему аккаунту

В настройках профиля доступна кнопка `Подключить VK ID`. Операция требует
активной сессии и недавнего повторного входа по email и паролю. OAuth intent
содержит `link_user_id`, привязан к текущему браузеру и действует 10 минут.
Если выбранный VK ID уже принадлежит другому аккаунту, автоматического
объединения не происходит.

Администратор может найти ошибочные связи аккаунт–карточка на странице
`/admin/requests` и снять связь. Удаляется только `users.player_id`, сама
карточка и результаты игрока сохраняются; обязательная причина записывается в
Audit как `account.player_unlink`.
